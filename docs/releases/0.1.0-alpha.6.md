# Screen Sharing Proxy 0.1.0-alpha.6

The first app release with an experimental relay. On the controlling Mac, enter
the host IPv4 address in **Proxy** and click **Connect**. Apple's Screen Sharing
opens after the relay reserves its sockets; sign in there and select the mode.
**Stop Relay** and quitting the app stop and reap its owned system Ruby process.
The app has no ten-minute experiment cutoff. **Settings** contains optional ports;
**Diagnostics** retains one-click private ZIP collection. Session counters can be
saved separately as JSON. The existing icon and DMG layout are preserved.

The relay now accepts the viewer's discovery connection followed by login and
session reconnections. Peer closure/reset ends the current pair without killing
the listener; unsent TCP bytes are counted. Backpressure remains bounded.

TCP forwarding writes newly read bytes immediately, avoids redundant buffer
copies and reads larger bounded chunks. On a local Apple silicon synthetic test,
throughput rose from 2.45 to 7.11 GiB/s and median small-message round-trip time
fell from 58.5 to 48.7 microseconds. These local measurements are not an end-to-end
Screen Sharing speed guarantee.

The user confirmed video, keyboard and mouse after selecting High Performance
on a previously working pair. Its report nevertheless recorded roughly 1.96 GB
through TCP and zero forwarded UDP datagrams. The app therefore shows observed
transport instead of claiming verified High Performance. The intended UDP media
path, restricted-viewer operation, audio and longer-session stability remain
unverified. Direct sharing may still be faster; the color difference is unresolved.

Apple silicon, macOS 14+, system Ruby. No gems or Python installation required.
Ad-hoc signed and not notarized. This release does not change firewall rules,
interfaces, routes or display settings. CI builds and verifies the DMG, native
app lifecycle, reports, signatures and mounted layout; CI does not prove a live
High Performance session. See the included installation guide.
